## 管理指南 {#admin-guide}


### 概述 {#overview}


OpenSIPS h350 模块使 OpenSIPS SIP 代理服务器能够访问存储在 LDAP [RFC4510](https://tools.ietf.org/html/rfc4510) 目录中的 SIP 账户数据，该目录包含 H.350 [H350](https://www.itu.int/rec/T-REC-H.350/en) *commObject*。ITU-T H.350 建议书对用于存储实时通信（RTC）账户数据的 LDAP 对象类做了标准化。特别是 *H.350.4* [H350 4](https://www.itu.int/rec/T-REC-H.350.4/en) 定义了一个名为 *sipIdentity* 的对象类，其中包含针对 SIP 账户数据的属性定义，例如 SIP URI、SIP 摘要认证用户名/密码或服务级别。这样就可以用厂商中立的方式存储 SIP 账户数据，并让不同实体（如 SIP 代理、数据配置或计费应用程序）以标准化格式访问这些数据。


*ViDe H.350 Cookbook* 是部署 H.350 目录的良好参考。除了 H.350、LDAP 及相关标准的一般性介绍，该文档还说明了如何搭建 H.350/LDAP 目录，并讨论了不同的部署场景。


h350 模块使用 OpenSIPS LDAP 模块把 H.350 属性值导入 OpenSIPS 路由脚本的变量空间。该模块导出若干函数，用于在 OpenSIPS 路由脚本中解析并存储 H.350 属性值，使脚本编写者可以实现基于 H.350 的 SIP 摘要鉴权、呼叫前转、SIP URI 别名到 AOR 的重写，以及服务级别解析。


#### H.350 commObject LDAP 条目示例 {#example-h350-commobject-ldap-entry}


以下示例展示了一个存储 SIP 账户数据的典型 H.350 commObject LDAP 条目。


```c title="存储 SIP 账户数据的 H.350 commObject 示例"
Attribute Name                Attribute Value(s)
--------------                -----------------

# 标识该 commObject 所有者的 LDAP URI，通常 
# 指向企业目录中的某个条目
commOwner	ldap://dir.example.com/dc=example,dc=com??one?(uid=bob)	

# 该 commObject 的唯一标识符，用于引用 
# 该对象，例如从企业目录中引用 
commUniqueId                  298217asdjgj213	

# 决定该 commObject 是否应在白页中列出
commPrivate                   false

# 该账户的有效 SIP URI（也可用于存储诸如 DID 的
# 别名 SIP URI）
SIPIdentitySIPURI             sip:bob@example.com                 
                              sip:bob@alias.example.com
                              sip:+1919123456@alias.example.com
# SIP 摘要认证用户名	
SIPIdentityUserName           bob

# SIP 摘要认证密码
SIPIdentityPassword           pwd

# SIP 代理地址
SIPIdentityProxyAddress       sip.example.com

# SIP 注册服务器地址
SIPIdentityRegistrarAddress   sip.example.com

# 呼叫偏好：无应答 20 秒后以及遇忙时前转到语音信箱
callPreferenceURI             sip:bob@voicemail.example.com n:20000
                              sip:bob@voicemail.example.com b
	
# 账户服务级别
SIPIdentityServiceLevel	      long_distance
                              conferencing
                              
# H.350 对象类
objectClass                   top
                              commObject
                              SIPIdentity
                              callPreferenceURIObject
            
```

### 导出的参数 {#exported-parameters}


#### ldap_session (string)


用于 H.350 查询的 LDAP 会话名称，在 LDAP 模块配置文件中定义。


默认值：""


```opensips title="ldap_session 参数用法"
modparam("h350", "ldap_session", "h350");
            
```


#### base_dn (string)


用于对 H.350 条目开始 LDAP 搜索的基础 LDAP DN。为获得最佳性能，应将其设置为 H.350 对象的直接上级。


默认值：""


```opensips title="base_dn 参数用法"
modparam("h350", "base_dn", "ou=h350,dc=example,dc=com");
            
```


#### search_scope (string)


H.350 查询的 LDAP 搜索范围，取值为 "one"、"base" 或 "sub" 之一。


默认值："one"


```opensips title="search_scope 参数用法"
modparam("h350", "search_scope", "sub");
            
```


### 导出的函数 {#exported-functions}


#### h350_sipuri_lookup(sip_uri)


该函数在 LDAP 中查询 SIPIdentitySIPURI 为 `sip_uri` 的 H.350 commObject。`sip_uri` 参数首先会按照 LDAP 过滤器字符串的规则进行转义。LDAP 搜索结果会存储在内部，可以通过 *h350_result* 系列函数或 OpenSIPS LDAP 模块的 *ldap_result* 系列函数访问。


出现内部错误时，该函数返回 `-1`（FALSE）；如果没有找到 `sip_uri` 匹配的 H.350 commObject，则返回 `-2`（FALSE）。如果找到 `n` 个 H.350 commObject，则返回 `n` > 0（TRUE）。


该函数可在 REQUEST_ROUTE、ONREPLY_ROUTE、FAILURE_ROUTE 和 BRANCH_ROUTE 中使用。


**sip_uri (string)**


要在目录中查找的 H.350 SIPIdentitySIPURI。


**`n` > 0 (TRUE):**


- 找到 `n` 个 H.350 commObject。


**`-1` (FALSE):**


- 发生了内部错误。


**`-2` (FALSE):**


- 未找到 H.350 commObject。


该函数可在 REQUEST_ROUTE、FAILURE_ROUTE、BRANCH_ROUTE 和 ONREPLY_ROUTE 中使用。


```opensips title="用法示例"
#
# 对被叫进行 H.350 查找
#

if (!h350_sipuri_lookup("sip:$rU@$rd"))
{
    switch ($retcode)
    {
    case -2:
        xlog("L_INFO", 
             "h350 callee lookup: no entry found in H.350 directory");
        exit;
    case -1:
        sl_send_reply(500, "Internal server error");
        exit;
    }
}

# 现在可以使用 h350_result* 或 ldap_result* 函数
            
```

#### h350_auth_lookup(auth_username, "username_avp_spec/pwd_avp_spec")


该函数在 H.350 目录中查询 SIP 摘要鉴权凭据。它会在 H.350 目录中查找 SIPIdentityUserName 为 `auth_username` 的 commObject。如果找到这样的 commObject，就把 SIP 摘要鉴权用户名和密码分别存储到 AVP `username_avp_spec` 和 `pwd_avp_spec` 中。之后就可以使用 AUTH 模块的 *pv_*_authorize* 系列函数执行 SIP 摘要鉴权。


如果找到 H.350 commObject，该函数返回 `1`（TRUE）；出现内部错误时返回 `-1`（FALSE）；如果没有找到匹配的 commObject，则返回 `-2`（FALSE）。


该函数可在 REQUEST_ROUTE、ONREPLY_ROUTE、FAILURE_ROUTE 和 BRANCH_ROUTE 中使用。


**auth_username (string)**


要在目录中查找的 H.350 SIPIdentityUserName。


**username_avp_spec (var)**


鉴权用户名 AVP 的定义，例如 `$avp(username)`。


**pwd_avp_spec (var)**


鉴权密码 AVP 的定义，例如 `$avp(pwd)`。


**`1` (TRUE):**


- 找到 H.350 commObject，并把 SIP 摘要鉴权凭据存储到 `username_avp_spec` 和 `pwd_avp_spec` 中。


**`-1` (FALSE):**


- 发生了内部错误。


**`-2` (FALSE):**


- 未找到 H.350 commObject。


该函数可在 REQUEST_ROUTE、FAILURE_ROUTE、BRANCH_ROUTE 和 ONREPLY_ROUTE 中使用。


```opensips title="用法示例"
# -- 鉴权参数 --
modparam("auth", "username_spec", "$avp(auth_user)")
modparam("auth", "password_spec", "$avp(auth_pwd)")
modparam("auth", "calculate_ha1", 1)

# -- h350 参数 --
modparam("h350", "ldap_session", "h350")
modparam("h350", "base_dn", "ou=h350,dc=example,dc=com")
modparam("h350", "search_scope", "one")


route[1]
{
    #
    # 基于 H.350 的 SIP 摘要鉴权 
    #
     
    # 对所有未包含 Auth 头域的请求发起质询
    if (!(is_present_hf("Authorization") || 
          is_present_hf("Proxy-Authorization")))
    {
        if (is_method("REGISTER"))
        {
            www_challenge("example.com", 0);
            exit;
        }
        proxy_challenge("example.com", 0);
        exit;
    }

    # 使用鉴权用户名（$au）从 H.350 获取摘要密码
    if (!h350_auth_lookup($au, 
                          "$avp(auth_user)/$avp(auth_pwd)"))
    {
        switch ($retcode)
        {
        case -2:
            sl_send_reply(401, "Unauthorized");
            exit;
        case -1:
            sl_send_reply(500, "Internal server error");
            exit;
        }
    }

    # REGISTER 请求
    if (is_method("REGISTER"))
    {
        if (!pv_www_authorize("example.com"))
        {
            if ($retcode == -5)
            {
                sl_send_reply(500, "Internal server error");
                exit;    
            }
            else {
                www_challenge("example.com", 0);
                exit;
            }
        }

        consume_credentials();
        xlog("L_INFO", 
             "REGISTER request successfully authenticated");
        return(1);
    }

    # 非 REGISTER 请求
    if (!pv_proxy_authorize("example.com"))
    {
        if ($retcode == -5)
        {
            sl_send_reply(500, "Internal server error");
            exit;    
        }
        else {
            proxy_challenge("example.com", 0);
            exit;
        }
    }

    consume_credentials();
    xlog("L_INFO", "$rm request successfully authenticated");
    return(1);
}
            
```


#### h350_result_call_preferences(avp_name_prefix)


该函数解析 H.350 commObject 的 callPreferenceURI 属性，该 commObject 必须已经通过 *h350_*_lookup* 或 *ldap_search* 获取。callPreferenceURI 是一个多值属性，用于存储诸如遇忙前转或无条件前转之类的呼叫偏好规则。*Directory services architecture for call forwarding and preferences* [H350 6](https://www.itu.int/rec/T-REC-H.350.6/en) 定义了一种简单呼叫前转规则的格式：


`target_uri type[:argument]`


在 SIP 环境中，`target_uri` 通常就是该前转规则的目标 SIP URI，不过它也可以是任意类型的 URI，例如指向 CPL 脚本的 HTTP 指针。`type` 规定了四种不同的取值：`b` 表示"遇忙前转"，`n` 表示"无应答前转"，`u` 表示"无条件前转"，`f` 表示"目的地未找到时前转"。可选的 `argument` 是一个字符串，表示应在前转之前等待的时间，单位为毫秒。


```c title="H.350 callPreferenceURI 简单呼叫前转规则示例"
# 示例 1：
# 15 秒无应答后前转到 sip:voicemail@example.com：

callPreferenceURI: sip:voicemail@example.com n:15000

# 示例 2：
# 无条件前转到 sip:alice@example.com：

callPreferenceURI: sip:alice@example.com u

# 示例 3：
# 目的地未找到时前转到 sip:bob@example.com 和 sip:alice@example.com
#（分叉）：

callPreferenceURI: sip:bob@example.com f
callPreferenceURI: sip:alice@example.com f
            
```


*h350_result_call_preferences* 按照以下规则把这些呼叫前转规则存储为 AVP：


```c
#
# 存储前转规则目标 URI 的 AVP
#
            
AVP name  = avp_name_prefix + '_' + type
AVP value = target_uri

#
# 存储前转规则 argument 的 AVP
#

AVP name  = avp_name_prefix + '_' + type + '_t'
AVP value = argument / 1000
            
```


上面的示例 1 会产生两个 AVP：`$avp("prefix_n") = "sip:voicemail@example.com"` 和 `$avp("prefix_n_t") = 15`。


示例 2：`$avp("prefix_u") = "sip:alice@example.com"`。


示例 3：`$avp("prefix_f[1]") = "sip:bob@example.com"` 和 `$avp("prefix_f[2]") = "sip:alice@example.com"`。


随后就可以在 OpenSIPS 路由脚本中使用这些 AVP 来实现所需的行为。


如果 H.350 callPreferenceURI 属性包含一个或多个符合上述简单呼叫前转规则语法的值，该函数返回成功解析的简单呼叫前转规则数量（TRUE）。出现内部错误时返回 `-1`（FALSE）；如果没有任何规则匹配，或者未找到 callPreferenceURI 属性，则返回 `-2`（FALSE）。


该函数可在 REQUEST_ROUTE、ONREPLY_ROUTE、FAILURE_ROUTE 和 BRANCH_ROUTE 中使用。


**avp_name_prefix (string)**


呼叫前转规则 AVP 的名称前缀，如前所述。


**`n` > 0 (TRUE):**


- 找到 `n` 条简单呼叫前转规则。


**`-1` (FALSE):**


- 发生了内部错误。


**`-2` (FALSE):**


- 未找到简单呼叫前转规则，或 callPreferenceURI 不存在。


该函数可在 REQUEST_ROUTE、FAILURE_ROUTE、BRANCH_ROUTE 和 ONREPLY_ROUTE 中使用。


```opensips title="用法示例"
#
# 对被叫进行 H.350 查找
#

... h350_sipuri_lookup("sip:$rU@$rd") ...

#
# 把 H.350 呼叫偏好存储到 AVP 中
#

if (!h350_result_call_preferences("callee_pref_") && ($retcode == -1))
{
    sl_send_reply(500, "Internal server error");
    exit;
}

# $avp(callee_pref_u)   == CFU URI
# $avp(callee_pref_n)   == CFNR URI
# $avp(callee_pref_n_t) == CFNR 超时时间（秒）
# $avp(callee_pref_b)   == CFB URI
# $avp(callee_pref_f)   == CFOFFLINE URI

#
# 无条件前转（CFU）示例
#

if ($avp(callee_pref_u) != NULL)
{
    # 把 CFU URI 填入 R-URI 和额外分支
    # --> 请求可以分叉
    $ru = $avp(callee_pref_u);
    $avp(callee_pref_u) = NULL;
    while ($avp(callee_pref_u)!=NULL) {
        $branch = $avp(callee_pref_u);
        $avp(callee_pref_u) = NULL;
    }
    sl_send_reply(181, "Call is being forwarded");
    t_relay();
    exit;
}
            
```


#### h350_result_service_level(avp_name_prefix)


*Directory services architecture for SIP* [H350 4](https://www.itu.int/rec/T-REC-H.350.4/en) 定义了一个名为 SIPIdentityServiceLevel 的多值 LDAP 属性，可用于在 LDAP 目录中存储 SIP 账户的服务级别值。该函数解析 SIPIdentityServiceLevel 属性，并把所有服务级别值存储为 AVP，以便稍后在 OpenSIPS 路由脚本中取用。该函数访问由 *h350_*_lookup* 或 *ldap_search* 调用所获取的 H.350 commObject。


生成的 AVP 名称形式为 `avp_name_prefix + SIPIdentityServiceLevel attribute value`，其整型值为 `1`。


```opensips title="SIPIdentityServiceLevel 取值及生成的 AVP 示例"
SIPIdentityServiceLevel: longdistance
SIPIdentityServiceLevel: international
SIPIdentityServiceLevel: 900

调用 h350_result_service_level("sl_") 之后，路由脚本中可以
使用以下 AVP：

$avp("sl_longdistance") = 1
$avp("sl_international") = 1
$avp("sl_900") = 1
            
```


该函数返回所添加的 AVP 数量（TRUE）；出现内部错误时返回 `-1`（FALSE）；如果未找到 SIPIdentityServiceLevel 属性，则返回 `-2`（FALSE）。


该函数可在 REQUEST_ROUTE、ONREPLY_ROUTE、FAILURE_ROUTE 和 BRANCH_ROUTE 中使用。


**avp_name_prefix (string)**


服务级别 AVP 的名称前缀，如前所述。


**`n` > 0 (TRUE):**


- 添加了 `n` 个 AVP。


**`-1` (FALSE):**


- 发生了内部错误。


**`-2` (FALSE):**


- 未找到 SIPIdentityServiceLevel 属性。


该函数可在 REQUEST_ROUTE、FAILURE_ROUTE、BRANCH_ROUTE 和 ONREPLY_ROUTE 中使用。


```opensips title="用法示例"
#
# 对主叫进行 H.350 SIP 摘要鉴权
#

... h350_auth_lookup("$au", ...) ...

#
# 把主叫的服务级别存储为 AVP
#

if (!h350_result_service_level("caller_sl_") && ($retcode == -1))
{
    sl_send_reply(500, "Internal server error");
    exit;
}

#
# 根据服务级别 AVP 做出路由决策
#

if ($avp(caller_sl_international) != NULL)
{
    t_relay();
} 
else {
    sl_send_reply(403, "Forbidden");    
}
exit;
            
```
